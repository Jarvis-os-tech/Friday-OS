================================================================================
UI/UX DESIGN GENERATION PROMPT — "Lovable-style AI Agent Orchestration Console"
================================================================================
PURPOSE
Generate a high-fidelity UI/UX design (desktop-first web app, ~1440px viewport) for a
single-page AI agent workbench inspired by the Lovable.ai visual language. The product
is a voice/command-driven agent console where a user delegates work to sub-agents and
watches their progress in real time. Three required functional surfaces must be present
and clearly legible in the design:

  1. AGENT DELEGATION  — a panel/flow for spawning and managing sub-agents
  2. LIVE ACTIVITY FEED — a streaming, real-time event log of agent actions
  3. COMMAND BAR       — a prominent, keyboard-first input for prompts and commands

--------------------------------------------------------------------------------
A. DESIGN LANGUAGE (Lovable aesthetic — apply faithfully, do NOT deviate)
--------------------------------------------------------------------------------
• Background: warm cream #f7f4ed (NEVER pure white #ffffff).
• Primary text / headings / dark surfaces: charcoal #1c1c1c (not pure black).
• Secondary / body text: muted gray #5f5f5d.
• Light button text on dark: off-white #fcfbf8.
• Borders: passive = #eceae4 (1px); interactive = rgba(28,28,28,0.4) (1px).
• Grays are DERIVED from #1c1c1c at opacities (0.03 / 0.04 / 0.4 / 0.82 / 0.83),
  never arbitrary hex grays — keeps tonal unity.
• Typeface: humanist variable sans (Camera Plain Variable / substitute DM Sans via
  Google Fonts). Weights: 400 (body, UI, buttons, links), 600 (headings, max weight —
  NEVER 700). Optional special display weight 480.
• Headlines: negative letter-spacing that scales with size — -1.5px @60px, -1.2px @48px,
  -0.9px @36px, normal @16px. Tight line-height (1.00–1.10) at display sizes.
• Buttons:
    - Primary dark: #1c1c1c bg, #fcfbf8 text, 6px radius, 8px 16px padding, signature
      multi-layer inset shadow: rgba(255,255,255,0.2) 0px 0.5px 0px inset,
      rgba(0,0,0,0.2) 0px 0px 0px 0.5px inset, rgba(0,0,0,0.05) 0px 1px 2px 0px.
    - Ghost/outline: transparent bg, 1px solid rgba(28,28,28,0.4), 6px radius.
    - Pill/icon buttons: full 9999px radius, used ONLY for toggles + icon actions.
    - Active state: opacity 0.8.
    - Focus: soft diffused shadow rgba(0,0,0,0.1) 0px 4px 12px (no sharp outlines).
• Cards/containers: cream #f7f4ed bg, 1px solid #eceae4 border, NO drop shadow by
  default (borders do containment). Radius scale: 4px micro, 6px buttons/inputs,
  8px compact, 12px standard cards, 16px large containers, 9999px pills.
• Depth is intentionally SHALLOW: no floating cards; rely on warm borders. Only notable
  shadow is the dark-button inset. Focus rings use blue rgba(59,130,246,0.5) (a11y only).
• Atmosphere: behind hero/header, a barely-visible warm multi-color gradient wash
  (soft pinks, oranges, blues) — atmospheric, not loud. No saturated accent colors.
• Whitespace: editorial generosity. Base unit 8px; section vertical padding 80–208px.
  Max content width ~1200px, centered. Tight internal card spacing (12–24px) contrasted
  with wide section gaps.
• Responsive intent (document, even if desktop mock): nav → hamburger <768px; card
  grids 3→2→1; command bar stays sticky/full-width; spacing 128px+ → 64px on mobile.

--------------------------------------------------------------------------------
B. PAGE STRUCTURE / LAYOUT
--------------------------------------------------------------------------------
Single screen, 3-region app shell on cream:

TOP — Sticky top navigation bar (cream, subtle or no border on scroll)
  • Left: wordmark/logo (humanist, charcoal).
  • Center/right: nav links (14–16px, weight 400, charcoal, underline-on-hover) e.g.
    Agents · Activity · Memory · Docs.
  • Far right: ghost "Log in" + dark primary CTA "New Agent" (inset shadow).
  • Optional: a small pill voice/toggle button (9999px) for voice mode.

CENTER — Main work area (two-column on desktop)
  LEFT COLUMN (~62%): the COMMAND BAR + delegation workspace
  RIGHT COLUMN (~38%): the LIVE ACTIVITY FEED (persistent side rail)

--------------------------------------------------------------------------------
C. FUNCTIONAL SURFACE 1 — COMMAND BAR (primary focal element)
--------------------------------------------------------------------------------
• A large, inviting prompt input fixed at the TOP of the left column (or floating just
  below nav). Cream surface, 1px solid #eceae4, 6px radius, focus → blue ring
  rgba(59,130,246,0.5). Placeholder text in #5f5f5d, e.g. "Describe a task or type
  / to command your agents…".
• Below the input, a row of suggestion pills: 1px solid #eceae4 borders, full-pill or
  6px radius, cream bg — e.g. "Build landing page", "Research competitors", "Summarize
  inbox". These are the quick-delegate chips.
• Keyboard-first: show a subtle "⌘K" hint affordance on the right of the bar.
• Pill-shaped action buttons at the input's right edge: a voice-record toggle and a
  "plan mode" toggle (9999px radius, opacity 0.5 default → 0.8 active).
• On submit, the bar hands the task to the delegation layer (Surface 2) and the feed
  (Surface 3) begins streaming.

--------------------------------------------------------------------------------
D. FUNCTIONAL SURFACE 2 — AGENT DELEGATION
--------------------------------------------------------------------------------
A bordered card region ("Agents" / "Delegation") showing the orchestration model:
• A grid or list of AGENT CARDS. Each card (cream bg, 1px solid #eceae4, 12px radius):
    - Agent name + role (e.g. "Researcher", "Builder", "Reviewer"), 20px weight 400 title.
    - Status pill: idle / running / done — render as a small full-pill chip, muted gray
      when idle, charcoal when running (no saturated green/red; stay warm-neutral, use
      opacity/charcoal to signal state).
    - A one-line description (14px, #5f5f5d).
    - A slim progress indicator (charcoal at low opacity bar) when running.
• A "Delegate" control: dark primary button "Assign Task" (inset shadow) and a ghost
  "Spawn Agent" button. Visual metaphor = a parent agent routing work to child agents.
• Show a lightweight dependency/route diagram (optional, bordered box): parent → child
  agents as connected nodes, drawn in charcoal hairlines on cream — keep it minimal and
  editorial, not a busy node graph.
• Microcopy: "FRIDAY routes your command to the right agent and streams results below."

--------------------------------------------------------------------------------
E. FUNCTIONAL SURFACE 3 — LIVE ACTIVITY FEED (right rail, persistent)
--------------------------------------------------------------------------------
A tall, bordered panel (cream bg, 1px solid #eceae4, 16px radius) titled "Live Activity":
• Streaming event list, newest on top. Each row:
    - Left: a small pill/dot status marker (charcoal hairline ring, filled when active).
    - Agent name (14px weight 400, #1c1c1c) + action verb ("researching", "writing",
      "delegating to Builder", "done").
    - Timestamp/caption in #5f5f5d, 14px.
    - Optional 1-line result preview in muted gray.
• Rows separated by 1px #eceae4 hairlines (no cards-within-cards).
• A soft "live" pulse indicator (charcoal at low opacity, gentle) at the panel header.
• Quiet, calm motion: new entries fade/slide in — convey "real-time" without clutter.
• If empty/initial: a warm placeholder ("Your agents' activity will stream here") in
  #5f5f5d.

--------------------------------------------------------------------------------
F. SUPPORTING / HERO MOMENT (optional top band)
--------------------------------------------------------------------------------
If generating a marketing-style hero variant instead of the app shell: centered single
column on cream with the warm gradient wash behind. 60px headline (Camera Plain / DM
Sans weight 600, -1.5px, #1c1c1c): e.g. "Delegate the work. Watch it happen." Subhead
18px weight 400 #5f5f5d: "A voice- and command-driven agent console with live activity
and one-tap delegation." Dark CTA "Start Building" (inset shadow) + ghost "See it live".
Below: a stylized product preview card showing the command bar + agent cards + feed.
Otherwise, prioritize the app-shell layout (B–E) as the main deliverable.

--------------------------------------------------------------------------------
G. DO / DON'T CHECKLIST (enforce during generation)
--------------------------------------------------------------------------------
DO: cream #f7f4ed base; charcoal #1c1c1c text; derive grays via opacity; inset-shadow
dark buttons; #eceae4 borders for containment (no heavy shadows); two weights (400/600);
full-pill radius only for toggles/icon pills; soft shadow focus; editorial whitespace;
show all three surfaces (command bar, agent delegation, live activity feed) legibly.
DON'T: use pure white bg; bold 700; saturated accent colors; sharp focus outlines; heavy
card drop-shadows; 9999px radius on rectangular buttons; increase heading letter-spacing;
omit any of the three required functional surfaces; mix border styles (#eceae4 passive vs
rgba(28,28,28,0.4) interactive only).

--------------------------------------------------------------------------------
H. OUTPUT SPEC
--------------------------------------------------------------------------------
Deliver as a polished, production-looking UI mock (HTML/CSS artifact OR high-fidelity
image). Desktop 1440px width. Include realistic-but-fictional sample content in the
command bar, agent cards, and activity feed so the three functionalities read instantly.
Accessibility: sufficient charcoal-on-cream contrast; visible focus states; ≥8px touch
padding. Tone: warm, calm, premium, "approachable AI tool" — never clinical or cold.
